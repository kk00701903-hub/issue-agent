# Agent Hub 사용자 매뉴얼 (v0.6)

## 1. 설치와 실행 (Windows)
1. 압축을 풀고 폴더를 연다(경로에 한글이 있어도 된다).
2. `install.bat` 더블클릭 — Python 확인, SDK 설치, .env 생성, 자체 시험까지 한다.
3. `.env` 를 열어 `ANTHROPIC_API_KEY` 를 넣는다. 혼자 쓰면 `HUB_PASSWORD` 는 비워도 된다.
4. `run.bat` 더블클릭 — 브라우저가 http://127.0.0.1:4830 으로 열린다. 이 창을 닫으면 서버가 꺼진다.

## 1-1. PC에 앱으로 설치 (PWA)
1. `run.bat` 으로 서버를 켜고 크롬 또는 엣지에서 http://127.0.0.1:4830 을 연다.
2. 화면 오른쪽 위 「앱으로 설치」 버튼을 누른다(버튼이 안 보이면 주소창 오른쪽의 설치 아이콘 또는 메뉴 ⋮ → 「Agent Hub 설치」).
3. 바탕화면·시작 메뉴·작업 표시줄에 Agent Hub 아이콘이 생기고, 주소창 없는 별도 창으로 열린다. 아이콘을 오른쪽 클릭하면 승인함·자동화·활동으로 바로 갈 수 있다.
4. 앱은 이 PC의 관리 서버에 붙는 창이다. 서버가 꺼져 있으면 「관리 서버가 꺼져 있습니다」 안내가 뜨고, 서버를 켜면 4초 안에 저절로 돌아온다.
5. PC를 켤 때마다 서버가 창 없이 자동으로 켜지게 하려면 `autostart-on.bat` 을 한 번 실행한다. 끌 때는 `autostart-off.bat`.
- 데이터(실행 기록·승인)는 앱에 저장되지 않고 항상 서버에서 새로 받는다. 앱이 저장해 두는 건 화면 파일뿐이다.
- 고객사 브랜딩(`hub/config.json`)을 바꾸면 앱 이름·색도 따라 바뀐다. 아이콘 그림은 `hub/static/icons/` 의 PNG를 바꾼다.

## 2. 화면 (v0.6 — Jira식 구성)
위쪽 막대에 「만들기」·검색·도움말·설정이 있고, 왼쪽 사이드바에서 화면을 고른다(「[」 키나 왼쪽 위 ⋮⋮ 로 접기).

| 메뉴 | 하는 일 |
| --- | --- |
| 요약 | 처음에는 「시작하기」 목록(시험 실행 → API 키 → 첫 실제 실행 → 앱 설치 → 자동 실행, 다 하면 사라짐), 승인 대기·검수 실패·완료·오늘 비용 카드, 상태 개요(도넛), 에이전트별 작업량과 하루 한도, 최근 활동·최근 작업, 그룹 개요 |
| 보드 | 작업을 「대기·작업 중 / 검수 / 승인 대기 / 완료 / 반려·오류」 열의 카드로 본다. 검색·계정·담당 에이전트·「오류 있는 것만」으로 거르고, 「묶기」로 계정별·담당별 줄을 나눈다. 카드를 누르면 작업 상세 창이 열린다. 승인 대기 카드를 「완료」로 끌어 놓으면 승인, 「반려·오류」로 끌어 놓으면 반려 확인 창이 뜬다(확인을 눌러야 처리됨) |
| 캘린더 | 계정별 한 달 콘텐츠 계획표. 「한 달 계획 만들기」로 난이도(주 3·5·7회)·시간·주제·유형을 고르면 달력이 채워지고, 칸을 눌러 제목을 적거나 「이 주제로 만들기」로 작업을 만든다. 실제 만든 작업도 그 날 칸에 붙는다 |
| 목록 | 같은 작업을 표로 본다. 머리글을 누르면 정렬되고, 「내보내기」로 보이는 목록을 CSV(엑셀)로 저장한다 |
| 승인함 | 왼쪽 대기열에서 고르면 오른쪽에 상세가 열린다. 승인·반려와 메모. 검수 실패 건은 승인 버튼이 꺼진다 |
| 자동화 | 흐름(워크플로우) 편집기. AI로 만들기·재생·끌어 고치기(4장) |
| 에이전트 | 그룹별 에이전트 표(상태·역할·도구·금지·실행 건수). 그룹 줄을 누르면 접히고, 에이전트 줄을 누르면 오른쪽에 상세(흐름 위치·최근 작업·정의 파일)가 열린다 |
| 모니터 | 기본은 「사무실」: Firefly로 그린 실제 사무실 그림 위에 Blender로 만든 직원이 앉아 일한다. 모든 움직임은 실제 기록 그대로다 — 러너 실행 상태와 훅 기록(본 세션이 답하는 중, 서브에이전트에게 맡긴 일 시작·끝, 최근 2분 안 도구 사용)을 따른다. 「공통」 방 큰 책상은 총괄(PC에서 대화하는 Claude Code 본 세션), agents.json 에 없는 기본 서브에이전트(Explore 등)는 「도우미」로 잠깐 나타난다. 이름표에 지금 하는 일(맡은 일 또는 마지막 도구·파일)이 보인다. 지어낸 동작은 없다. 팀마다 방 하나(위쪽 팀 이름으로 바꿈) — ㄱ자 큰 책상이 팀장 자리(그 팀 첫 에이전트), 칸막이 자리가 팀원. 작업 중=타자, 승인 기다림=손 들기·「!」, 차단·오류=머리 감싸기·빨간 표시, 대기=숨 쉬기, 예정=반투명. 동작이 바뀔 때 부드럽게 섞여 넘어가고, 승인 대기가 되면 결재함까지 걸어오거나 서류가 날아간다. 이름표·사람을 누르면 오른쪽에 최근 작업, 결재함을 누르면 승인함. 예전 블록 사무실은 「3D 블록」: 에이전트마다 책상·캐릭터가 있고 작업 중이면 타자 치며 화면에 코드가 흐르고, 승인 기다림이면 손을 들고 「나」 책상까지 서류를 들고 걸어오며, 차단이면 빨간 경광등, 오류면 연기, 대기면 가끔 커피 마시러 감. 일이 넘어가면 서류가 다음 책상으로 날아감. 끌어 돌리기·휠 확대·두 번 눌러 다가가기·「나」 책상 누르면 승인함. 그 밖에 오늘 처리율, 에이전트 카드(픽셀 캐릭터가 작업 중이면 움직임·상태·한도), 별자리 연결도(작업 중인 선에 점이 흐름, 누르면 최근 작업), 릴스 흐름 단계별 건수, 6시간 활동. 「전체 화면」으로 벽 모니터에 띄운다 |
| 활동 | 에이전트 도구 사용·훅 차단·상태 변경 기록(탭으로 거름)과 작업 기록(work-log.md) |
| 프로젝트 설정 | 라이선스 키, 제품 정보, 운영 한도(전체·에이전트별), 모델(작업별 제공자·키 유무), 앱 설치, 테마·데스크톱 알림, 단축키 |

**작업 상세 창**: 왼쪽에 승인·반려 버튼, 검수 결과, 후킹, 미리보기, 장면, 캡션·소개 댓글, 기록. 오른쪽에 세부 정보(담당·계정·BGM·음성·비용 등)와 진행 단계. 작업 번호(예: AH-3)는 로고 글자와 만든 순서로 붙는다. Esc 로 닫는다.

**만들기(C)**: 계정·유형·시리즈·주제를 고르면 실제 실행 명령을 만들어 주고(복사해서 PC 터미널에서 실행, 비용 발생), 「시험 실행」은 비용 없이 가짜 결과물로 승인 흐름을 확인한다.

**위쪽 막대**: 검색칸에 글자를 넣으면 맞는 작업이 바로 뜬다(Enter 는 목록에서 보기). 종 아이콘은 새 상태 변경·훅 차단 알림. 오른쪽 동그라미(나)에서 테마(시스템 따름·밝게·어둡게)를 바꾼다.

**단축키**: `/` 검색, `C` 만들기, `J`·`K` 다음·이전 작업(승인함·상세 창), `G` 다음 `S`·`B`·`L`·`C`·`I`·`A`·`T`·`M`·`V` 로 요약·보드·목록·캘린더·승인함·자동화·에이전트·모니터·활동, `[` 사이드바, `?` 도움말, `Esc` 닫기.

테마 기본값은 PC 설정을 따른다(어두운 테마면 화면도 어둡게). 예전 주소(`#home` `#flow` `#log`)도 그대로 열린다.


**작업 순서(v0.6.1)**: 첫 화면 「오늘 할 일」이 지금 할 단계를 알려 준다. 위쪽·왼쪽 메뉴의 「1. 만들기 → 2. 진행 확인 → 3. 승인하기 → 4. 게시하기」 순서대로 하면 된다.
- 1. 만들기: 계정·주제를 고르고, 실제 실행 명령을 복사해 프로그램 폴더의 cmd 창에 붙여 넣는다(방법이 화면에 있음). 오늘 캘린더 계획이 있으면 「이 계획으로 채우기」.
- 2. 진행 확인: 보드. 검수 실패·실행 오류는 작업 창의 「같은 주제로 다시 만들기」.
- 3. 승인하기: 승인함.
- 4. 게시하기: 캡션·소개 댓글 복사 → 인스타 앱에서 콘텐츠 예약 → 「예약했어요」. 자동 게시는 없다.

## 3. 릴스 한 편 만들기 (실제 실행)
```
python -m hub.runner --account top.pick00 --series 전세 --topic "전세 계약 전 확인 3가지"
```
- 계정: `top.pick00` `top.pick01` `ojeongkkul`. 인물 릴스는 `--type person`.
- 끝나면 승인함에 「승인 대기」 또는 「검수 실패」로 뜬다. 검수 실패는 오류 목록을 보고 반려하거나, 에이전트가 고치게 다시 실행한다.
- 승인은 「게시 준비 완료」 표시다. 실제 게시·예약은 인스타 콘텐츠 예약에서 직접 한다.

## 4. 흐름(워크플로우)
**AI로 만들기(기본)**
1. 「자동화」 메뉴에서 그룹을 고르고 「✨ AI로 만들기」를 누른다.
2. 원하는 흐름을 한두 문장으로 적는다. 예) 「오늘 전세 뉴스로 주제 조사 → 쇼츠 자막 참고해 릴스 패키지 제작 → 규칙 검수 → 내가 승인 → 영상 제작 → 예약 화면까지」
3. 「흐름 만들기」를 누르면 AI가 그룹의 에이전트 목록을 보고 노드와 선을 만든다. 안전 규칙(게시·제출·커밋 같은 마지막 버튼은 사람 단계, 크롬 통제 뒤에는 사람 단계)은 AI 결과 위에 코드로 한 번 더 맞춘다.
4. 만든 흐름이 한 번 재생된다. 확인하고 「저장」을 누른다. 저장 전에는 반영되지 않는다.
- AI 호출은 기본 Claude(`.env` 의 `ANTHROPIC_API_KEY`). `hub/config.json` 의 `model_routes.flow` 로 DeepSeek·Kimi 등 다른 제공자를 고를 수 있다(docs/alt-models.md). 키가 없으면 규칙 기반으로 만들고 화면에 그렇게 표시한다.
- 맞는 에이전트가 없는 단계는 「새 에이전트」 표시가 붙는다. 그 단계는 에이전트를 새로 정의해야 실제로 돌아간다.

**보기**
- 선 위로 점이 흘러가며 작업 방향을 보여 준다. 지금 실행 중인 에이전트 상자는 빛나고 「실행 중 n」 표시가 붙으며, 그 앞뒤 선이 진하고 빠르게 흐른다.
- 승인 단계 상자에는 「승인 대기 n」이 붙는다. 점선으로 흐린 상자는 아직 연결 안 된 「예정」 에이전트다.
- 「▶ 흐름 재생」: 한 건이 처음부터 끝까지 상자를 차례로 지나가는 모습을 보여 준다.

**직접 고치기**
- 왼쪽 목록을 누르면 상자가 생긴다. 상자를 끌어 옮기고, 오른쪽 ● 를 끌어 다른 상자 왼쪽 ○ 에 놓으면 연결된다. 상자·선을 누르고 Delete 키로 지운다. 오른쪽 「속성」에서 이름·담당·종류·메모를 고친다.
- 「맞춤」 「정렬」 「−/+」로 화면을 정리한다.

## 5. 크롬 통제
`docs/browser-setup.md` 참고. 요약: 크롬을 `--remote-debugging-port=9222 --user-data-dir=E:\chrome-agent-profile` 로 띄우고 작업 계정만 로그인한다. 게시·제출·결제·삭제 버튼은 에이전트가 누르지 못한다.

## 6. 라이선스
- 처음 실행한 날부터 30일은 평가판이다. 상단 띠에 남은 일수가 보인다.
- 끝나면 실행이 멈추고 화면은 열린다. 프로젝트 설정에서 키를 넣으면 바로 풀린다.
- 키는 고객사 이름(`hub/config.json` → `branding.customer_name`)과 짝이다.

## 7. 자주 묻는 것
- **훅이 뭔가요?** 에이전트가 도구를 쓰기 전에 돌아가는 검사다. 커밋·삭제·규칙 파일 수정·최종 버튼 클릭을 막는다. 끌 수 없고, 규칙 값은 `hub/rules.json` 에서 바꾼다.
- **비용이 걱정됩니다.** `hub/config.json` 의 `daily_budget_usd` 를 넘으면 그날은 실행이 거부된다.
- **외부에서 접속할 수 있나요?** 안 된다. 127.0.0.1 에만 열린다. 열려면 코드와 보안 설정을 바꿔야 한다(판매 체크리스트 참고).

## 도구(판매 단위) — v1.0
- 왼쪽 「도구」에서 도구를 켜고 끄며, 일할 에이전트를 눌러 연결한다. 연결한 에이전트만 그 도구의 일을 맡는다(실행기가 확인).
- 인스타그램 도구: 계정(ID·이름·음성/무음·인물 소개·캘린더 주제)과 검수 규칙(금지 BGM·시리즈 로테이션·음성·읽기 속도)을 화면에서 정한다. 저장 위치는 `data/tools/instagram.json`.
- 「1. 만들기」 위쪽에서 도구를 고른다. 인스타그램 밖의 도구는 결과가 문서(result.md)로 나오고 승인함에서 본다.
- 명령: `python -m hub.runner --tool <도구> --topic "…"`(인스타그램은 `--account` 도 필요).
- 이용권: 설정 → 웹 콘솔 연결(연결 코드). 판매자 본인 PC는 옛 키를 그대로 쓴다(`allow_legacy_license`).
- 판매 구조·배포: `docs/release-checklist.md`, `docs/cloud-deploy.md`, `tools/README.md`.
- 크몽 전문가 서비스 도구(kmong): 서비스 제목·요약·상세·3단 패키지·FAQ 를 만들고 크몽 등록 규칙(외부 연락처·절대 표현·무조건 보증·패키지 가격 차이 1만 원·최소 금액·전자책 미리보기 5장)을 코드로 검수. 승인 뒤 등록 화면 임시저장까지, 「검수 요청」은 사람이. 명령: `python -m hub.runner --tool kmong --topic "…" --param kind=service`.
- 모니터 사무실 그림은 v3(모든 의자가 열린 바닥 쪽, 팀장 책상 뒤가 열려 있음). 걸을 때는 자리 → 통로 점 → (책상 모서리를 돌아) 결재함 순서로 움직인다.
